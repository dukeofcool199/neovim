1. CONCEPT                                                         *ai-concept*
                                                                  *ai-registry*

One registry, `config/ai/registry.nix`, holds every credential, endpoint and
role -> model binding. Plugins read it instead of carrying their own literals,
so a model is set in one place and every consumer follows.

A role is a job, not a place. Point one at a local endpoint or a hosted agent
by setting its `backend` and `model`; there is no separate "remote" role.

Four layers resolve, later winning:

	registry  ->  tier  ->  project  ->  session

	registry	the committed default
	tier		$NVIM_AI_TIER, an opt-in overlay
	project		`require("ai").setup()` from .nvim.lua
	session		:AiModel, :AiBackend, <leader>9m

|:AiStatus| names the layer each role is currently taking its value from.

==============================================================================
2. ROLES                                                             *ai-roles*

	edit		<leader>9v	99 rewrites the selection
	search		<leader>9s	99 searches the project
	cli		<leader>a*	sidekick's terminal agents
	ask				codecompanion chat (dormant)
	agent				avante's sidebar (dormant)
	completion			minuet ghost text (dormant)
	next-edit			minuet duet (dormant)

`edit` and `search` drive a CLI agent, so their backend must be one that
names a provider 99 can load. Three do:

	opencode	the `opencode` binary, its own credentials.
			Models are `provider/model`: `openai/gpt-5.5`.
	claude-code	the `claude` binary, your own login.
			Models are Anthropic's: `claude-opus-5`.
	claude-go	the same claude binary through the `claude-go`
			wrapper, which points it at OpenCode Go and
			supplies that credential. Models are go's:
			`minimax-m3`, `qwen3.8-max`, `kimi-k3`.

All three are fenced: opencode by a permission set denying every edit outside
99's tmp file plus bash and task, the claude pair by a --settings allow-list
run with --permission-prompts none. opencode is the default on both roles.

claude-go exists because the claude CLI is the better 99 driver while the
OpenCode Go subscription is the cheaper model pool; it is the two together.
Nothing claude-* runs on it -- go serves no Anthropic models.

Its model list is shorter than go's own. go serves 42 ids over two protocols
and the claude CLI can only speak one of them: a model outside the Anthropic
set answers `/v1/messages` with ModelProtocolUnsupported, whatever the
request says. The registry carries the eleven that answer, so the picker
cannot offer a row that will not run. Re-derive the list by POSTing a
one-token message to `/v1/messages` for every id `/v1/models` returns.

3. PROJECT CONFIGURATION                                           *ai-project*

Per-project defaults live in `.nvim.lua` at the project root, Neovim's own
exrc (|exrc|), which this config enables. It is executable Lua and must be
trusted once with |:trust| on first open.

exrc runs after the main config, so `require("ai")` is ready by then.

Setting claude-code and a model as the default for this project: >lua

	-- .nvim.lua
	require("ai").setup({
	  edit   = { backend = "claude-code", model = "claude-opus-5" },
	  search = { backend = "claude-code", model = "claude-sonnet-5" },
	})
<
Both fields are needed when changing agent: each agent has its own model
namespace. opencode wants `provider/model` (`openai/gpt-5.5`), claude-code a
bare Anthropic id (`claude-opus-5`), claude-go one of the OpenCode Go ids
listed for it (`minimax-m3`). A model from the wrong namespace fails at run
time, not at startup.

:AiStatus will then show both roles with source `project`.

Unknown role names and unknown fields warn rather than error, so a typo in a
project file never breaks startup.

4. RECIPES                                                         *ai-recipes*

Claude for rewrites, opencode for search — the common split, since search
reads widely and opencode is the fenced one: >lua

	require("ai").setup({
	  edit   = { backend = "claude-code", model = "claude-opus-5" },
	  search = { backend = "opencode",    model = "openai/gpt-5.5" },
	})
<
Only change the model, keeping the agent the role already has: >lua

	require("ai").setup({
	  edit = { model = "openai/gpt-5.6-fast" },
	})
<
Pin sidekick's terminal claude for this project too. `cli` names its tool by
binary rather than backend, so it takes a bare model: >lua

	require("ai").setup({
	  cli = { model = "claude-opus-5" },
	})
<
A cheap model for a throwaway repo: >lua

	require("ai").setup({
	  edit   = { backend = "claude-code", model = "claude-haiku-4-5-20251001" },
	  search = { backend = "claude-code", model = "claude-haiku-4-5-20251001" },
	})
<
Everything on claude, one table: >lua

	local claude = { backend = "claude-code", model = "claude-sonnet-5" }
	require("ai").setup({ edit = claude, search = claude })
<
Try an agent for this session only, leaving .nvim.lua alone — press
<leader>9m and pick a `claude-code` row, or: >vim

	:AiBackend edit claude-code
	:AiModel edit claude-opus-5
<
|:AiReset| drops session and project layers and returns to the registry.

==============================================================================
5. COMMANDS                                                       *ai-commands*

						*:AiStatus*
:AiStatus		Every role: model, endpoint, backend, auth, and which
			layer supplied it. Start here.

						*:AiModel*
:AiModel {role} {model}
			Set a role's model for this session. Completes role
			names, then that role's models.

						*:AiBackend*
:AiBackend {role} {backend}
			Move a role to another backend, leaving its model
			alone. Use when you want the agent changed but not
			the model; <leader>9m changes both together.

						*:AiPick*
:AiPick [{role}]	Telescope picker. Without a role, pick the role first.

						*:AiReset*
:AiReset [{role}]	Drop session and project overrides. Without a role,
			reset every role.

						*:AiDoctor*
:AiDoctor		Check each ollama role's model against the
			capabilities ollama reports for it.

						*:AiAuth*
:AiAuth [{name}]	Credential status, never key material. With ! it
			probes `pass` and clears the cache.

						*:AiTier*
:AiTier [{name}]	Switch the $NVIM_AI_TIER overlay at run time. No
			argument, or `small`, returns to the defaults.

6. KEYMAPS                                                         *ai-keymaps*

99, under <leader>9: >

	9v	rewrite the selection (visual mode, `edit` role)
	9s	search the project (`search` role)
	9m	pick the agent and model for `edit`
	9M	pick the agent and model for `search`
	9x	stop all requests
	9o	open the last interaction
	9l	view logs
<
9m and 9M list every model across every agent, each row naming its own, so
picking a claude row moves the role onto claude in one keypress: >

	claude-code  claude-opus-5
	claude-code  claude-sonnet-5
	claude-go    minimax-m3
	claude-go    qwen3.8-max
	opencode     openai/gpt-5.5
	opencode     openai/gpt-5.6-fast
<
The claude-code rows come from the registry, since the claude CLI cannot
enumerate its own models; the claude-go rows are OpenCode Go's /v1/models,
fetched when the picker opens.
sidekick's terminal agents, under <leader>a, run the `cli` role. <C-g>
toggles the overlay. See |ai-roles|.

==============================================================================
7. LUA API                                                             *ai-api*

						*ai.setup()*
require("ai").setup({roles})
			Apply project overrides. The .nvim.lua entry point.
			Returns |ai.status()|.

						*ai.set()*
require("ai").set({role}, {spec} [, {layer}])
			Override one role. {spec} may be a bare model string.
			{layer} is "session" (default) or "project".

						*ai.role()*
require("ai").role({name})
			The fully resolved role: model, backend, endpoint,
			url, provider, and `source`. Returns nil if unknown.

						*ai.status()*
require("ai").status()
			One row per role, as |:AiStatus| prints.

						*ai.pick()*
require("ai").pick({name} [, {cb}])
			Raise the picker for a role. A role on a CLI agent
			gets the flat agent-qualified list.

						*ai.agent_models()*
require("ai").agent_models({cb})
			Every model across every CLI agent, as
			{backend=, model=} rows.

						*ai.reset()*
require("ai").reset([{name}])
			Drop overrides. Without a name, every role.

						*ai.on_change()*
require("ai").on_change({cb})
			Called with (name, role) whenever a role changes.
			How sidekick keeps its argv current.

8. TROUBLESHOOTING                                           *ai-troubleshooting*

A model picker shows nothing ~
The agent could not enumerate its models. opencode needs `opencode models` to
work on the command line; claude-code carries a list in the registry instead,
since the claude CLI cannot enumerate its own; so does claude-go, whose list
is the subset of OpenCode Go that speaks the Anthropic protocol.

99 reports a role is "not a CLI agent 99 can drive" ~
The role's backend names an HTTP endpoint (opencode-go) rather than an agent.
Only backends with a provider work: `opencode` and `claude-code`.

A 99 run fails immediately after switching agent ~
Likely a model from the other agent's namespace. Check |:AiStatus|: a
claude-code role holding `openai/...`, an opencode role holding a bare
`claude-...`, or a claude-go role holding any `claude-...` at all, is the
tell. <leader>9m sets both together and avoids it.

claude-go warns on every run ~
Two lines on stderr, both expected and neither fatal. `unrecognized_model`
says the id is not in the CLI's own catalogue, which no go id is; the
request still carries that id to the gateway unaltered. The other says
claude.ai connectors are off, because a gateway credential takes precedence
over the claude.ai login. Neither reports a failed request -- a real failure
arrives as a `claude-go:` line naming what the gateway objected to. stdout
carries only the answer.

The longer complaint about the model catalog and auto-compact is gone: the
wrapper names the context window ($CLAUDE_CODE_MAX_CONTEXT_TOKENS, 200k),
which is what the CLI could not look up for an id it does not know.

99 reports a credential error on claude-go ~
The wrapper resolves $OPENCODE_API_KEY first and `pass show ai/opencode-go`
on a miss, the same order as |:AiAuth|. With neither, it exits before
spawning claude and says so. `claude-go -p hi --model minimax-m3` in a
shell isolates whether the problem is the credential or Neovim.

The gateway answers ModelProtocolUnsupported ~
That id is one of go's, but it is not served over the Anthropic protocol,
which is the only one the claude CLI speaks. Nothing configures around it --
pick a model the registry lists for claude-go.

A claude-go request used to hang ~
It cannot any more, and this is why it did: the CLI treats every gateway
failure as retryable, so a rejected key became an exponential backoff that
printed nothing and never exited, and 99 waits on exit. The wrapper now caps
a non-interactive run at 300 seconds ($CLAUDE_GO_TIMEOUT), then asks the
gateway what it objects to and prints that answer -- "Invalid API key.",
"Model X is not supported." -- on stderr. The cap applies to any --print run
and to any run whose stdout is not a terminal, which covers 99 and every
smoke test; a real interactive session is left uncapped, since there the
backoff is on screen and interruptible.

.nvim.lua seems ignored ~
It needs trusting once with |:trust|, and `require("ninetynine")` no longer
exists — a file still calling it errors. Use |ai.setup()|.

Which layer won? ~
|:AiStatus| prints `source` per role: default, tier:NAME, project, session.
